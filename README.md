# Тепло — локальный помощник по отоплению

Первая версия интерфейса на чистом TypeScript и Vite, без UI-фреймворков. Логика организована в классы. Все шрифты и иконки локальные, внешних запросов для ответов нет.

## Запуск

Нужен Node.js 20.19+ или 22.12+ (рекомендуется актуальная LTS-версия).

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite, обычно http://127.0.0.1:5173. На OpenServer запускайте проект через Vite: исходный TypeScript не исполняется напрямую через PHP/Apache.

```bash
npm run build    # Проверка TypeScript и сборка в dist/
npm run preview  # Просмотр собранной версии
```

Сборку `dist/` можно обслуживать обычным локальным HTTP-сервером.

## Возможности

- Адаптивный чат, стартовые примеры вопросов и боковая панель диалогов.
- Постепенное появление тестового ответа и кнопка остановки.
- Enter отправляет сообщение, Shift + Enter добавляет строку.
- Создание, переключение и удаление диалогов.
- История сохраняется в localStorage этого браузера и адреса сайта. Она не шифруется, не синхронизируется и пропадёт при очистке данных сайта. При недоступном хранилище отображается сообщение.
- Ответы выводятся как текст: пользовательский HTML не исполняется.

## Структура

```text
src/
  app/ChatApp.ts             — состояние приложения и управление диалогами
  components/ChatView.ts     — стартовый экран и сообщения
  components/MessageInput.ts — поле ввода и отправка
  components/icons.ts        — встроенные SVG-иконки
  services/ChatService.ts    — демонстрационный провайдер ответов
  services/StorageService.ts — сохранение и загрузка истории
  types/chat.ts             — типы и контракт ChatProvider
  styles/main.css           — оформление и мобильная версия
  main.ts                   — точка входа
```

## Подключение локальной модели — следующий этап

Нейросеть пока **не подключена**. `ChatService` выдаёт заранее подготовленные ответы по ключевым словам и имитирует поток. Он не выполняет реальную диагностику и не подбирает оборудование.

Чтобы подключить модель, реализуйте контракт `ChatProvider`: метод `stream(messages, signal)` должен возвращать `AsyncIterable<string>` с фрагментами ответа и учитывать `AbortSignal`. Передайте экземпляр провайдера вторым аргументом в `new ChatApp(root, provider)`.

Далее нужен локальный сервер для обращения к модели и поиска по базе документации. Сам интерфейс не требует изменений. API-ключи и другие секреты не следует помещать в клиентский код.
