# Тепло — локальный помощник по отоплению

Чат на чистом TypeScript и Vite и локальный сервис на Node.js/TypeScript. Логика организована в классы. Первый рабочий сценарий — ориентировочный расчёт расхода воды: уточнения, сохранение параметров диалога и источники из локальной базы. Нейросеть не подключена; ответы собираются правилами и шаблонами, без внешних ИИ-сервисов.

## Запуск

Нужен Node.js 20.19+ или 22.12+ (рекомендуется актуальная LTS-версия).

```bash
npm install
npm run data:prepare
npm run dev
```

Откройте адрес Vite, обычно http://127.0.0.1:5173. Команда запускает интерфейс, компиляцию TypeScript в режиме наблюдения и сервис бота на http://127.0.0.1:3001. Запросы `/api` идут через прокси Vite; сервис слушает только `127.0.0.1`. При изменении кода сервис перезапускается, параметры диалогов остаются в браузере. Ctrl+C останавливает процессы. На OpenServer исходный TypeScript не исполняется напрямую через PHP/Apache.

Пример: «Посчитай расход для 5 кВт» → «Вода» → «Ориентировочный расчёт для воды» → «60/40 °C». Результат — 0,215 м³/ч (215 л/ч), с формулой, допущениями и ссылкой на полный раздел. Далее «А если 50/40?» даёт 430 л/ч по сохранённой нагрузке.

```bash
npm test                  # Проверки сервиса, диалога, калькулятора и клиентского провайдера
npm run data:check        # Проверки данных и эталонов
npm run data:check-generated
npm run build             # Проверка TypeScript, интерфейс в dist/, сервис в dist-server/
npm run start:server      # Запуск собранного сервиса
npm run preview           # В другом терминале: интерфейс с прокси /api
```

Для отдельного запуска при разработке: `npm run dev:server` и `npm run dev:ui`. При обслуживании `dist/` другим HTTP-сервером потребуется настроить прокси `/api` к сервису бота.

Настройки — в [.env.example](.env.example): для разработки скопируйте его в `.env.local`. `BOT_PORT` меняет порт сервиса и прокси, `VITE_BOT_API_URL` — базовый адрес API клиентского провайдера. При отдельном запуске собранного сервиса `BOT_PORT` передаётся переменной окружения (PowerShell: `$env:BOT_PORT='3002'`). Источники доступны по `/api/sources/:id`; при переносе API этот маршрут также нужно проксировать.

Демо-провайдер сохранён: задайте `VITE_CHAT_MODE=demo` в `.env.local` и перезапустите Vite. Режим явно отмечен в интерфейсе. Ошибки API не включают демо автоматически.

## Возможности

- Адаптивный чат, стартовые примеры вопросов и боковая панель диалогов.
- Расчёт расхода воды, уточнения с кнопками быстрых ответов, формула и источники.
- Остановка запроса, обработка недоступности сервиса и тайм-аута. Готовый ответ сервиса показывается сразу; постепенный вывод остаётся в демо-режиме.
- Enter отправляет сообщение, Shift + Enter добавляет строку.
- Создание, переключение и удаление диалогов.
- История и параметры каждого диалога сохраняются в localStorage этого браузера и адреса сайта. Они не шифруются, не синхронизируются и пропадут при очистке данных сайта. При запросе история и параметры передаются локальному сервису; сервис их не сохраняет. При недоступном хранилище отображается сообщение.
- Ответы выводятся как текст: пользовательский HTML не исполняется.

## Структура

```text
src/
  app/ChatApp.ts             — состояние приложения и управление диалогами
  components/ChatView.ts     — стартовый экран и сообщения
  components/MessageInput.ts — поле ввода и отправка
  components/icons.ts        — встроенные SVG-иконки
  services/ApiChatProvider.ts — провайдер локального API
  services/ChatService.ts    — явно выбираемый демо-провайдер
  services/StorageService.ts — сохранение и загрузка истории
  types/chat.ts             — типы и контракт ChatProvider
  styles/main.css           — оформление и мобильная версия
  main.ts                   — точка входа
server/                     — HTTP API, загрузка базы, правила, диалог и расчёт
shared/                     — контракт API и проверка состояния диалога
tests/                      — автоматические проверки первого среза
vite.config.ts              — прокси /api к локальному сервису
```

## Состояние разработки

Завершён [этап 3 — данные первого сценария](docs/stage-3-data.md). Начат [этап 4 — локальный сервис и диалог](docs/stage-4-service.md). При запуске сервис проверяет наличие, формат, происхождение и актуальность собранной базы; без неё запуск завершается с понятной ошибкой. Воспроизводимые данные в `data/generated/` не хранятся в Git.

Чат поддерживает только водяное приближение `0,86 × Q / Δt`. Вода и способ расчёта требуют подтверждения. Гликоль, паспортные свойства, подбор труб и насоса, фактический или минимальный расход котла не рассчитываются. Распознаваемые сообщения об опасности получают первичный шаблон из подготовленных эталонов до уточнений. Правила ограничены и не являются полноценной диагностикой. Профессиональная проверка и независимый контрольный набор остаются открытыми задачами.

Выбранный подход и порядок работ описаны в [docs/development-plan.md](docs/development-plan.md): собственная небольшая нейросеть для определения намерения, проверенные структурированные данные, логика диалога, расчёты и цитаты из инженерной базы приложения «Отопление». Вопросы задаются в браузере, а нейросеть и обработка работают на сервере: сначала локальном, затем на сервере приложения «Отопление». Готовые среды запуска моделей не используются.

Провайдер подключается через `new ChatApp(root, provider)`. Контракт `stream(messages, signal, state?)` возвращает `AsyncIterable<string | ChatAnswer>`: демо выдаёт фрагменты текста, API — готовый ответ с источниками, вариантами уточнений и новым состоянием. Отмена проверяется до применения ответа и состояния.
