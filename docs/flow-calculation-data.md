# Данные расчёта расхода теплоносителя

Первый срез этапа 3 — `hydraulics.flow`. Источник: [глава 05, «Нагрузка и расход»](knowledge/installation-guide/05-pipe-sizing-and-hydraulics.md#нагрузка-и-расход). Формулы, ограничения и объяснение сверены с локальной базой. Профессиональная проверка остаётся открытой; классы обучения этим изменением не утверждаются.

## Исходные файлы и подготовка

- [data/definitions/hydraulics.flow.json](../data/definitions/hydraulics.flow.json) — формальный контракт параметров, единицы, ограничения, зависимости, формулы, статусы результатов, уточнения и небольшой словарь.
- [data/fixtures/hydraulics.flow.json](../data/fixtures/hydraulics.flow.json) — 30 синтетических случаев, включая связь с семью эталонами. Это проверки разработки, не независимый контрольный набор и не результат извлечения параметров из текста.
- [scripts/prepare-knowledge.mjs](../scripts/prepare-knowledge.mjs) — подготовка данных без соседнего проекта, сети и новых зависимостей.

Из корня проекта:

```bash
npm run data:check             # Эталоны, контракт, арифметика, состояния диалога и защита источников
npm run data:prepare           # Сверка эталонов и сборка данных
npm run data:check-generated   # Сравнение готового файла с текущими источниками
```

Результат для расхода — `data/generated/hydraulics.flow.json`. Общая команда также готовит отдельные файлы [геометрии трубы, скорости и предварительного диаметра](pipe-calculation-data.md), [потерь по Kv и напора](pressure-calculation-data.md). Каталог исключён из Git: файлы воспроизводятся из версионируемых определений, примеров и локальной базы. Отсутствующий или устаревший файл приводит к ошибке `data:check-generated`; эта команда ничего не переписывает.

Сборка сохраняет исходный коммит, SHA-256 входных файлов и десяти файлов снимка базы. Полный раздел «Нагрузка и расход» включается вместе с оговорками, заголовком главы, ссылкой, границами строк, хешем и статусами чисел. Семь эталонов включаются с явными учебными состояниями и описаниями всех их источников. Дополнительные ссылки на материалы и правила диалога не считаются подготовленными фрагментами инженерной базы.

Время сборки и абсолютный путь рабочего каталога в результат не входят. CRLF нормализуется в LF. Изменение источника, границ раздела или его хеша останавливает подготовку. Скрипт не обновляет манифесты и не подтверждает изменения базы автоматически.

## Входы и методы

Числа передаются конечными числовыми значениями в единицах контракта. Строки не преобразуются в числа. Преобразование единиц и извлечение из пользовательского текста предстоит реализовать на этапе 4; для нагрузки уже заданы коэффициенты Вт → кВт и кВт → кВт. Отсутствующие значения и `null` не получают значений по умолчанию.

| Метод | Необходимые данные | Результат и граница |
| --- | --- | --- |
| `water_approximation` | Нагрузка в кВт, подтверждённая вода, охлаждение | `0.86 × Q / Δt`, м³/ч, и л/ч; предварительная водяная оценка |
| `fluid_properties` | Нагрузка, среда, охлаждение, c в Дж/(кг·К), ρ в кг/м³, источник, состав и рабочая температура свойств | Массовый расход в кг/с и объёмный в м³/ч и л/ч при заданных условиях |
| `delta_ratio` | Прежнее и новое охлаждение, явное подтверждение неизменной нагрузки и свойств | Отношение нового объёмного расхода к прежнему; абсолютный расход не определяется |

Охлаждение задаётся положительным `water_delta_k` либо полной парой `supply_c` и `return_c`. Имя `water_delta_k` сохранено для совместимости с учебными состояниями эталонов; поле применимо и к другой среде. Если заданы оба представления, они должны совпадать с абсолютной погрешностью не более `0.000001 K`. Частичная пара температур требует уточнения даже при заданном перепаде: недостающую температуру автоматически не достраиваем.

При подаче ниже обратки, равных температурах или конфликте с перепадом нужно уточнение. Числа не переставляются и модуль разности не используется. Явный нулевой или отрицательный перепад, отрицательная нагрузка, неположительные свойства и неизвестные поля недопустимы. Нулевая нагрузка при положительном охлаждении даёт нулевую расчётную потребность; это не разрешение нарушать минимальный расход источника.

Для метода по свойствам требуются и теплоёмкость, и плотность: он выдаёт одновременно массовый и объёмный расход. Плотность не нужна для отдельной формулы массового расхода, но отдельная операция только для него пока не введена. Источник, состав и температура фиксируют происхождение чисел; сами по себе они не подтверждают достоверность или применимость свойств. Встроенных таблиц гликоля и паспортов нет.

Приближение `0.86` намеренно отличается от расчёта по c = 4180 и ρ = 1000: для 8 кВт и 20 К получаются соответственно 344 и около 344,498 л/ч. Проверка сохраняет это различие. Числа свойств смеси в учебном примере вымышлены для арифметики и не предназначены для подбора.

## Граница реализации

В [scripts/lib/flow-contract.mjs](../scripts/lib/flow-contract.mjs) находится проверка структурированных входов и арифметический эталон для подготовки данных. Строки формул не исполняются через `eval`. Состояния проверки — `ready`, `clarify` и `invalid`; `ready` означает достаточность структурированных данных для формулы, а не подтверждение инженерного решения.

Сервис, разбор текста, сбор параметров по истории, выбор метода и выдача ответа в чате относятся к этапу 4. Интерфейс пока использует демо-провайдер. Срез [скорости потока и внутреннего диаметра](pipe-calculation-data.md) подготовлен отдельно с оговорками о стенке трубы, сопротивлении и предварительном характере подбора.
