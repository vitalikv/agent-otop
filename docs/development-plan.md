# План разработки «Тепло»

Дата обновления: 30 октября 2026 года.

## Цель проекта

Создать чат-бота, который помогает владельцу частного дома разобраться с отоплением: схемами, подбором радиаторов и труб, подключением, монтажом, запуском и неисправностями. Ответы должны опираться на проверенные материалы и учитывать исходные данные пользователя.

Бот разрабатывается в этом проекте, а в будущем встраивается в приложение «Отопление» (`C:\OpenServer\domains\skeleton-wf`, папка `src-heating`). Основной пользователь первой версии — хозяин дома. Позже планируется расширение для монтажника, продавца и проектировщика.

Интерфейс — чистый TypeScript и Vite без UI-фреймворков. Логика приложения организована в классы. Используется собственная небольшая нейросеть, созданная и обученная с нуля; готовые среды запуска моделей, такие как Ollama, и предобученные модели в работе бота не используются. Для прототипа это ограничение снято решением от 31 октября 2026 года: проверяется открытая языковая модель на своём сервере (см. [пересмотр подхода](#решение-от-31-октября-2026-года-прототип-с-открытой-языковой-моделью)). Пользователь задаёт вопросы в браузере, а нейросеть, данные и обработка запросов работают на сервере: сначала на локальном, затем на боевом сервере приложения «Отопление». Внешние ИИ-сервисы не используются.

Обозначения: `[x]` — выполнено; `[ ]` — предстоит выполнить. План обновляется по мере разработки. Предлагаемые названия будущих классов, API и форматов можно уточнять при реализации.

## Выбранный подход

Подробное обоснование — в `custom-neural-network-proposal.md`. Кратко:

- Собственная нейросеть определяет тему и намерение запроса. Поиск, логика диалога, расчёты, проверка параметров и сборка ответа — обычный программный код.
- Технические факты хранятся в структурированном виде и вручную сверяются с источниками. Тексты используются для поиска пояснений и цитат.
- Ответ собирается из проверенных данных, шаблонов, расчётов и дословных цитат с указанием источника. Свободной генерации текста в первой версии нет.
- Разработка идёт вертикальным срезом: один сценарий проходит всю цепочку от вопроса до ответа, затем добавляются следующие.
- Каждое изменение проверяется на контрольном наборе вопросов, которые не используются при обучении.

```text
Вопрос, ответы на уточнения и состояние диалога
           ↓
Нормализация текста и извлечение параметров (правила)
           ↓
Определение намерения (своя нейросеть; до её готовности — правила)
           ↓
Логика диалога: хватает ли исходных данных?
           ↓
Уточняющий вопрос с вариантами ответа
или поиск в данных, расчёт и поиск по документации
           ↓
Ответ по шаблону, результат расчёта и цитаты с источниками

Браузер передаёт вопрос и состояние диалога на сервер;
все шаги обработки выполняются на сервере.
```

## Решение от 31 октября 2026 года: прототип с открытой языковой моделью

Пользователь хочет бота, который свободно отвечает на вопросы, а не только выбирает подготовленный текст. Своя сеть, обученная с нуля, этого не умеет. Поэтому для прототипа разрешены открытая предобученная языковая модель и среда её запуска на собственном сервере. Раздел «Выбранный подход» пока не меняется: его перепишут, если прототип себя оправдает. Тогда же перепроверят эталоны, которые на него ссылаются.

- **Разрешено.** Открытая модель с лицензией, допускающей платное использование: Qwen3, Apache 2.0. Среда запуска — llama.cpp, а для проверки на компьютере разработчика — LM Studio.
- **По-прежнему запрещено.** Внешние ИИ-сервисы не используются, вопросы пользователей не покидают сервер.
- **Сохраняется:**
  - правила опасности и диалог расхода срабатывают раньше модели;
  - модель отвечает только по фрагментам базы и ставит ссылки;
  - арифметику выполняет код через инструмент `calculate`;
  - 160 эталонов не передаются модели и служат проверкой.
- **Сервер.** Нужна видеокарта NVIDIA на 16–24 ГБ, 4–8 ядер, 16–32 ГБ оперативной памяти и диск NVMe на 100 ГБ. Предложенный сервер с L40S-16Q (16 ГБ виртуальной видеопамяти, 8 ядер, 12 ГБ памяти) подходит для модели на 8–14 млрд параметров. Оперативной памяти впритык. До аренды нужно уточнить у провайдера, как видеокарта делится между машинами и какая версия CUDA доступна.

Устройство прототипа и запуск описаны в [llm-prototype.md](llm-prototype.md).

## Правила работы с данными из сети

- У каждого технического факта сохранять источник: производителя, название документа, редакцию или дату, страницу, ссылку и дату получения.
- Помечать статус числа так же, как в инженерной базе: паспортное значение, расчётная зависимость, ориентир или учебный пример.
- Сверять каждую запись с оригиналом; устаревшие редакции помечать и не выдавать за актуальные.
- Проверять условия использования материалов: бот будет частью платного приложения. Хранить факты со ссылкой на источник, не копировать большие фрагменты текста. Оригиналы хранить локально вне Git.
- Вопросы с форумов и сервисов вопросов и ответов сохранять без имён, ников и других персональных данных, только текст и ссылку.
- Сторонние нейросети применяются только при разработке: для составления стартовых вопросов и переформулировок обучающих вопросов. Сгенерированные примеры помечаются и проверяются вручную, не попадают в независимый контрольный набор и не служат источником технических чисел.

## Где что работает

```text
Браузер: интерфейс чата
           ↓
Сейчас: сервис бота на локальном компьютере
Потом:  PHP-ручка приложения (вход и подписка) → сервис бота
           ↓
Сервис бота: нейросеть, данные, поиск, расчёты
```

Боевой вариант повторяет устройство сервиса раскладки тёплого пола (`skeleton-wf/services/layout`): сервис на Node.js слушает только петлевой адрес, а вход и подписку проверяет PHP. Веса сети и собранные данные остаются на сервере и пользователю не передаются.

## Требования к ресурсам

Обучение выполняется на компьютере разработчика: RTX 5070 Ti, 16 ГБ видеопамяти. Работа бота должна оставаться лёгкой:

- Браузер только показывает интерфейс и отправляет вопросы; бот не добавляет требований к устройству пользователя.
- Сервис бота работает на процессоре, без видеокарты: на боевом сервере её, вероятно, нет. Там четыре ядра, и их уже использует сервис раскладки.
- Предварительные ориентиры, проверяются на этапе 7: обработка вопроса — быстрее 100 мс без учёта сети; память сервиса — до 200–300 МБ.
- Размер сети ограничивают процессор сервера и время ответа, а не видеокарта для обучения.

## Текущее состояние

Работают интерфейс и первый срез локального сервиса на Node.js/TypeScript: расчёт расхода воды, уточнения, сохранение параметров в браузере и ответы с источниками из подготовленной базы. `ChatService` сохранён как явно выбираемый демо-режим; автоматически при ошибках сервиса он не включается. [Реализация и границы первого среза](stage-4-service.md).

Собственная сеть определения намерения подключена к сервису по решению пользователя, до появления контрольного набора. Правила опасности и диалог расхода остаются первыми. Сеть отвечает на остальные вопросы объяснениями намерений с источниками, а при низкой уверенности предлагает темы кнопками. Обучение и оценка пока выполнены на синтетических примерах, сгенерированные примеры не проверены вручную. [Данные, порядок обработки и ограничения](stage-5-intent-model.md).

Готов прототип с открытой языковой моделью: поиск по базе, выбор разделов моделью, инструмент расчёта и прогон эталонов. Он включается переменной `BOT_LLM_URL`. Прогона на настоящей модели ещё не было: скачана Qwen3-8B, проверка идёт через LM Studio. [Этап 5б](#этап-5б-прототип-с-открытой-языковой-моделью).

Направление выбрано: собственная нейросеть для определения намерения, проверенные данные, расчёты и управляемый диалог; обработка — на сервере. Первый сценарий — инженерные вопросы по базе `installation-guide` и расчёты по её формулам.

Главная задача сейчас — прототип с открытой языковой моделью (этап 5б):
1. Подключить скачанную Qwen3-8B в LM Studio и адаптировать к нему клиент.
2. Прогнать 160 эталонных вопросов на Qwen3-8B и на qwen2.5-coder-14b, прочитать часть ответов.
3. Qwen3-14B не скачивать заранее, а только если результат Qwen3-8B не устроит.
4. Если результат устроит, проверить скорость на арендованном L40S-16Q.

Для сети намерений (этап 5) остаются:
- визуальная проверка чата;
- ручная проверка сгенерированных примеров;
- сбор 50–100 независимых контрольных вопросов.

Решение по прототипу может сделать часть этих работ лишней.

При изменении источников запускать `npm run data:check`, `npm run data:prepare` и `npm run data:check-generated`. При изменении обучающих данных или обработки текста — `npm run train:data`, `npm run train:model` и `npm run train:check`: сервис не запустится с весами, обученными на другой обработке текста.
