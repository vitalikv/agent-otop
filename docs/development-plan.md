# План разработки «Тепло»

Дата обновления: 30 октября 2026 года.

## Цель проекта

Создать чат-бота на локальном сайте, который помогает разобраться с отоплением: монтажом, подбором труб и фитингов, настройкой и причинами неисправностей. Ответы должны опираться на документацию оборудования и учитывать исходные данные пользователя.

Интерфейс — чистый TypeScript и Vite без UI-фреймворков. Логика приложения организована в классы. Нейросеть и обработка базы знаний должны работать локально. После первоначального скачивания зависимостей и моделей обычная работа не должна требовать интернета.

Обозначения: `[x]` — выполнено; `[ ]` — предстоит выполнить. План обновляется по мере разработки. Предлагаемые названия будущих классов и API можно уточнять при реализации.

## Текущее состояние

Работает первая версия интерфейса. Настоящая нейросеть, сервер и база знаний пока не подключены. `ChatService` выбирает заранее подготовленные ответы по ключевым словам и имитирует потоковую генерацию. Эти ответы предназначены для проверки интерфейса, а не для реальной диагностики или подбора оборудования.

## Этап 6. Поиск по документации и ответы с источниками — RAG

Статус: не начат. Зависит от локального чата и подготовленной базы знаний.

RAG — поиск подходящих фрагментов документации и передача их модели вместе с вопросом. Для первой рабочей версии обучение собственной нейросети с нуля не требуется.

```text
Вопрос и контекст диалога
           ↓
Локальный поиск по базе знаний
           ↓
Найденные фрагменты + вопрос + правила помощника
           ↓
Локальная модель
           ↓
Ответ с указанием документов и страниц
```

- [ ] Выбрать локальную модель для построения поисковых представлений текста и локальное хранилище индекса.
- [ ] Реализовать индексацию, повторную индексацию и удаление документов.
- [ ] Добавить поиск с учётом точных обозначений моделей, артикулов и размеров; оценить сочетание текстового и векторного поиска.
- [ ] Учитывать уточняющие вопросы и сведения из предыдущих сообщений при поиске.
- [ ] Передавать найденные фрагменты в модель в пределах доступного контекста.
- [ ] Обрабатывать содержимое документов как данные, а не как инструкции, меняющие поведение помощника.
- [ ] Возвращать ссылки только на реально использованные источники, с документом, редакцией и страницей при наличии.
- [ ] Добавить отображение источников в интерфейсе и открытие соответствующего локального документа.
- [ ] При недостатке или противоречии источников сообщать об этом и уточнять условия, а не выдавать уверенный подбор.

Результат этапа: ответы по поддерживаемому оборудованию можно проверить по локальным документам.
