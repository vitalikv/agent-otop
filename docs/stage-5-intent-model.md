# Этап 5: собственная сеть определения намерения

Дата: 30 октября 2026 года. Этап начат. Первая версия сети обучена с нуля, сохранена в простом формате и выполняется на TypeScript с тем же результатом, что и в PyTorch. В сервис бота сеть не подключена: независимого контрольного набора нет, поэтому не подтверждено, что она лучше правил на человеческих вопросах (условие плана). Все оценки ниже получены на синтетических примерах разработки.

## Запуск

Окружение обучения создаётся один раз. Сервису бота Python не нужен.

```bash
python -m venv training/.venv
training/.venv/Scripts/python -m pip install -r training/requirements.txt --index-url https://download.pytorch.org/whl/cu128 --extra-index-url https://pypi.org/simple
```

На Linux и macOS путь к интерпретатору — `training/.venv/bin/python`. Сборка `cu128` нужна для RTX 5070 Ti; без видеокарты подойдёт обычная сборка `torch` той же версии.

```bash
npm run train:data    # Набор: тексты, классы, признаки, ответы правил → data/generated/intent-dataset.json
npm run train:model   # Обучение и проверка на процессоре; -- --device cuda — на видеокарте
npm run train:check   # Согласованность с набором, сверка с PyTorch, скорость и память
npm run intent        # Ввод вопросов построчно, вывод трёх вероятных намерений
```

Набор, веса, отчёт и контрольные логиты лежат в `data/generated/` и в Git не хранятся. Их можно воспроизвести: на одном компьютере повторное обучение даёт побайтно тот же файл модели и на процессоре, и на видеокарте. Результаты процессора и видеокарты отличаются между собой: у них разные генераторы случайных чисел для dropout. По умолчанию используется процессор.

## Классы и данные

Класс обучения — основное (первое) намерение записи из [словаря](question-intents.md), всего 46 классов. Класс «не по теме» — `scope.off_topic`. Дополнительные намерения 51 стартового вопроса в обучении не участвуют. В оценке есть отдельная метрика: совпал ли ответ сети с любым из размеченных намерений. Классы взяты из проекта разметки без изменений. Их утверждение остаётся открытым пунктом этапа 2.

| Происхождение | Примеров | Статус |
| --- | ---: | --- |
| Стартовые вопросы [question-annotations.json](question-annotations.json) | 155 | Приняты пользователем как полезные; разметка — черновик ИИ |
| Переформулировки стартовых вопросов, по две на вопрос | 310 | Сгенерированы ИИ, не проверены |
| Новые вопросы для намерений с малым числом примеров | 722 | Сгенерированы ИИ, не проверены |
| Всего | 1187 | От 24 до 50 примеров на класс |

SYN-131…135 исключены. Это ответы на уточнения, их намерение задаёт состояние диалога, а не текст. Причины записаны в [intent-config.json](../data/training/intent-config.json). Сгенерированные примеры хранятся в [data/training/ai/](../data/training/ai/) с пометками `origin: ai_generated` и `review_status: unreviewed`. В разделе `rules` каждого файла описано, по какому правилу размечались примеры. План требует ручной проверки сгенерированных примеров перед обучением. Пока её нет, модель годится только для разработки.

Сборка набора проверяет:
- все классы есть в словаре;
- переформулировки ссылаются на существующие вопросы;
- тексты не повторяются после нормализации (числа при сравнении не учитываются);
- в каждом классе не меньше 15 примеров.

Сохраняются хеши всех входов и кода признаков.

## Признаки и сеть

Признаки строит только класс `IntentFeaturizer` на TypeScript. Python получает готовые номера признаков, поэтому обучение и сервис не могут разойтись в обработке текста.

1. Нормализация текста (`TextNormalizer`): регистр, «ё», десятичная запятая, кВт/Вт, `16х2` и `16x2`. Затем каждая цифра заменяется на 0, чтобы числа не становились отдельными словами.
2. Слова (в одно слово объединяются и `60/40`, `0.3`), пары соседних слов и символьные n-граммы длиной 2–4 по слову с границами `<слово>`.
3. Хеш FNV-1a, 16 384 корзины. Каждый признак учитывается в тексте один раз.

Сеть: среднее векторов признаков (64 значения) → ReLU → линейный слой на 46 классов → softmax. Параметров 1 051 630, почти все — таблица векторов признаков. На запрос читается только несколько сотен её строк, поэтому вычисление занимает доли миллисекунды. Веса начинаются со случайных значений, предобученных моделей нет.

## Обучение и выбор параметров

- Используются AdamW, пакеты по 32 примера, 30 эпох и фиксированное начальное значение генератора.
- Качество проверяется пятикратной перекрёстной проверкой по группам. Вопрос и его переформулировки всегда попадают в одну группу, а группы каждого класса распределены по всем пяти частям.
- Этой же проверкой выбираются параметры из небольшой сетки в настройках. Отдельный контрольный набор она не заменяет.
- Пробные запуски показали, что дальнейший подбор почти ничего не даёт:
  - размер скрытого слоя 32–128;
  - dropout 0,2–0,5;
  - скорость обучения, число корзин и длины n-грамм.

  Разброс не превышал 1–2 процентных пунктов. Слой 128 точнее не стал, а таблица весов при нём удваивается.
- Время на этом компьютере: полный цикл с перекрёстной проверкой 45 с на процессоре и 25 с на видеокарте; итоговая сеть обучается за 1,5 с.

## Результаты перекрёстной проверки

| Показатель | Сеть | TF-IDF + логистическая регрессия | Правила этапа 4 |
| --- | ---: | ---: | ---: |
| Верное основное намерение | 70,1% | 70,6% | 7,8% |
| Верное намерение среди трёх самых вероятных | 88,0% | 89,3% | — |
| Macro-F1 | 0,711 | 0,716 | 0,098 |
| Стартовые вопросы: основное намерение | 61,3% | 60,0% | 8,4% |
| Стартовые вопросы: любое размеченное намерение | 66,5% | 66,5% | 8,4% |
| Опасная ситуация отнесена к одному из классов `safety.*` | 88,9% | 88,9% | 53,5% |
| Ложная опасность в безопасном вопросе | 1,1% | 1,1% | 0,7% |

Как понимать результаты:
- **Правила этапа 4.** Они распознают только расход воды и явные формулировки опасности, поэтому низкая доля почти полностью объясняется охватом.
- **Сеть и TF-IDF.** Сеть не лучше простой линейной модели на тех же признаках, разница в пределах разброса. Узкое место — объём и разнообразие данных, а не архитектура.
- **Лучше всего распознаются:** `system.zoning`, `units.convert`, `safety.gas`, `hydraulics.head`, `safety.hot_leak`.
- **Хуже всего распознаются:** `radiator.select`, `equipment.role`, `radiator.fittings` (около 34%). Также `heat_loss.explain`, `pipe.install`, `product.lookup` и `service.booking` (46%).
- **Частые путаницы:**
  - подбор радиатора ↔ его размещение;
  - подбор радиатора ↔ расчёт теплопотерь;
  - назначение узла ↔ радиаторная арматура.
- **Опасность.** Хуже всего распознаётся `safety.electric` (58%).

## Порог уверенности

Порог подбирается автоматически: это наименьшая уверенность, при которой точность принятых ответов на перекрёстной проверке не ниже `target_accepted_accuracy` (0,9). Сейчас порог 0,90: сеть уверенно отвечает на 34% вопросов, и 92% из них верны. Порог 0,7 дал бы 55% охвата при 88% точности.

При текущих данных сеть годится в основном для уточняющего вопроса: в 88% случаев верное намерение входит в три самых вероятных, и их можно предложить пользователю кнопками. Выбор порога зависит от разброса между запусками: на видеокарте получилось 0,80. Окончательный порог задаётся по независимому контрольному набору.

## Выполнение в сервисе

`server/IntentClassifier.ts` загружает `intent-model.json`. При загрузке он проверяет формат, классы, формы и размеры весов и отсутствие нечисловых значений. Вычисление повторяет PyTorch, суммирование идёт в двойной точности. Веса хранятся как массивы float32 в формате little-endian, закодированные base64 внутри JSON. Файл занимает 5,4 МБ.

`npm run train:check` проверяет три вещи:
- модель обучена на текущем наборе;
- признаки пересчитываются без изменений;
- логиты 300 примеров совпадают с PyTorch (максимальное отличие 6·10⁻⁶, класс совпадает везде).

Замеры на этом компьютере, один поток: загрузка 40 мс, рост памяти процесса около 54 МБ, определение намерения в среднем 0,04 мс. Это укладывается в ориентиры плана: до 100 мс на вопрос и 200–300 МБ памяти. Замеры на боевом сервере остаются задачей этапа 7.

## Границы

- **Сеть в ответах не используется.** Маршрутизация, расчёт расхода и шаблоны безопасности работают по правилам этапа 4.
- **Правила опасности остаются обязательным первым шагом.** Классы `safety.*` в сети могут только дополнить распознавание, не заменить его.
- **Независимой оценки нет.** Все числа получены на синтетических текстах, похожих на обучающие. На реальных обращениях качество, вероятно, будет ниже.
- **Сгенерированные примеры не проверены вручную.** Ошибки разметки в них переходят в сеть.
- **Не решено, когда подключать сеть к сервису.** Сначала нужны независимый контрольный набор (этап 2) и правила по всем намерениям для честного сравнения (этап 4).
